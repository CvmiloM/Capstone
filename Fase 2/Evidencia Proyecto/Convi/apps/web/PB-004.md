# PB-004 — Inicio de sesión

El formulario de Camilo se conserva. Ahora permite ingresar con correo y
contraseña usando Supabase Auth, y pide a la API confirmar que la cuenta y su
establecimiento están activos antes de conceder acceso.

## Recorrido

1. `/login` valida en el servidor el correo y que exista una contraseña.
   El correo se normaliza; la contraseña conserva sus espacios.
2. `signInWithPassword` comprueba las credenciales y escribe las cookies de
   sesión mediante el cliente SSR existente. La contraseña no se devuelve al
   navegador ni se guarda en CONVI o en registros de consola.
3. `/auth/sesion` identifica la cuenta mediante la sesión, con los controles
   de PB-127. No se acepta un perfil, escuela o destino indicado por el usuario.
4. Una cuenta pendiente, suspendida, revocada, sin membresía activa o de una
   escuela inactiva recibe el mismo rechazo general. Se cierra localmente el
   intento autenticado que no obtuvo acceso, conservando otras sesiones de
   esa identidad. Fallos de conexión y límites de intentos tienen mensajes
   simples, sin enviar respuestas internas de Auth.
5. ADMIN y CONVIVENCIA pendientes pasan a `/verificar-segundo-factor`. Si aún
   no vincularon una aplicación, esa pantalla continúa a PB-008. Vincular el
   factor y verificarlo siguen siendo pasos de PB-008/PB-009.
6. La cuenta autorizada continúa al portal de su perfil. Profesor y Apoderado
   no necesitan segundo factor obligatorio.

| Perfil      | Destino        |
| ----------- | -------------- |
| ADMIN       | `/admin`       |
| CONVIVENCIA | `/convivencia` |
| PROFESOR    | `/profesor`    |
| APODERADO   | `/apoderado`   |

Login y confirmación del segundo factor comparten esta misma correspondencia,
para que el paso de MFA tampoco termine en otro portal.

## Pantallas y límites

La pantalla y los campos del login conservan el diseño, componentes y CSS
existentes. Administración conserva su resumen de ejemplo y Profesor conserva
el portal de Fernando.

Convivencia y Apoderado no tenían páginas implementadas. Se agregaron entradas
protegidas simples para que cada perfil tenga un destino válido, reutilizando
la marca, tarjeta, fondo y colores actuales. Informan que sus secciones todavía
no están disponibles; no muestran estudiantes, casos ni información ficticia.
Sus funciones se implementan en sus propios backlogs.

Cada entrada vuelve a consultar la API, comprueba el perfil y, para Convivencia,
la verificación del segundo factor antes de mostrar el contenido. Los futuros
datos y acciones de los portales también deben pasar por la API autorizada,
respetando la escuela y permisos de cada registro.

PB-002 sigue a cargo de Camilo. No se modificó el registro del administrador
ni la activación por invitación pendiente de PB-003. El cierre de sesión desde
los portales conserva PB-006; el cierre local de un login rechazado es solo
limpieza de ese intento.

## Archivos

- `src/app/(publico)/acciones.ts`: conecta solo la acción `iniciarSesion`,
  conservando registro, activación y validaciones compartidas.
- `src/lib/supabase/cuenta.ts`: añade los cuatro destinos junto a la consulta
  de cuenta que ya existía en PB-009.
- `src/lib/supabase/servidor.ts`: espera la petición del usuario antes de
  crear el cliente de Auth, que revisa la sesión con la hora actual. Evita el
  aviso de Next al preparar el portal Profesor, sin cambiar sus datos ni permisos.
- `src/app/(publico)/verificar-segundo-factor/acciones.ts`: usa esos destinos.
- `src/app/(publico)/verificar-segundo-factor/formulario-verificacion.tsx`:
  ajusta el texto del enlace de continuación según exista un destino.
- `src/app/components/entrada-portal.tsx`: entrada y autorización compartidas
  para los dos perfiles que no tenían pantalla.
- `src/app/convivencia/page.tsx` y `src/app/apoderado/page.tsx`: páginas de
  esos perfiles, con carga de sesión dentro de Suspense.

PB-004 queda terminado y preparado para el commit de Sebastian. El ingreso

Para probarlo, abrir `/login`, intentar una contraseña incorrecta y después
ingresar con la correcta. Profesor debe llegar a sus cursos, Apoderado a su
entrada y Admin/Convivencia a la verificación del segundo factor. Si estos
últimos aún no tienen una aplicación vinculada, deben configurarla con PB-008
y continuar. Una cuenta suspendida debe recibir el rechazo general y no
obtener acceso a un portal.

No hay archivos de prueba, dependencias, migraciones ni cambios a Docker.
En este entorno se reinició solo web para reconocer las páginas nuevas y
después de compilar, ya que desarrollo y compilación usan la misma carpeta.
