# Convi: source audit architecture

Profile: standard, read-only source audit of the current filesystem snapshot (796 source/configuration files, approximately 4.7 MB). No Git metadata or real environment/credential files are read. Target source is never modified. No compatible previous Cloudflare coverage ledger or findings file exists; previous ZAP reports are contextual evidence, not source-confirmed findings or exclusions.

CONVI manages Chilean school convivencia records. Principals are anonymous browsers, authenticated identities awaiting membership, ADMIN, CONVIVENCIA, PROFESOR and APODERADO. Teachers act on assigned courses and their records; guardians see authorized pupils/cases; convivencia staff manage school cases and follow-up; admins manage academic data, accounts and imports. Protected resources include school/child records, evidence, original documents, account assurance, case communications and model context.

The pnpm monorepo uses Next.js 16.4.5/React 19.3.1, NestJS 12/Express, PostgreSQL/Supabase and Redis/BullMQ. An independent Python >=3.14 FastAPI service fronts Ollama embeddings/chat. Apps/api/src/main.ts bootstraps the API; apps/web/src/proxy.ts and App Router handle browsers; apps/ia/src/convi_ia/aplicacion.py handles IA HTTP. Deployment source includes Docker/Compose and Azure Container Apps Bicep. Local scripts can expose IA via Tailscale Funnel. The API is declared internal and web external in Azure source; actual deployed attachments and settings are unknown. Some introductory Docker docs are stale relative to current source.

Global SesionGuard is default-deny. IdentidadService uses Supabase getClaims plus getUser and current verified factors. Roles/school derive from active DB membership, not browser role fields. ADMIN/CONVIVENCIA require aal2 on operation routes; auth/sesion intentionally works before MFA. CuentaService re-resolves membership and assurance in a transaction, sets local role/context, checks session validity and uses school/resource predicates. Migrations force tenant RLS; finer teacher/guardian permissions rely on service predicates. Account invitation, activation, suspension, guardian grants and MFA resets form separate authority transitions.

Browser FormData reaches Server Actions and bearer-authenticated API forwarding. Uploads enter format/magic/extension checks, private Supabase storage and DB metadata; documents enter worker-based PDF/DOCX extraction, fragments, embeddings and RAG. CSV/XLSX imports have 5 MiB/5000-row/100-column bounds and large-XLSX worker routing. Evidence/documents have 25 MiB bounds. Reports, email drafts, rule jobs and AI outputs create derived copies. Follow both HTTP and queued paths. IA inputs/model outputs have source-visible token, schema, length and response limits; model text is not itself authority.

Comparable baseline: Ollama API contracts only; no meaningful comparable school product is established by source. Key starting paths: API common/auth/database/cuentas/registro; situaciones/academico/importaciones/documentos/orientacion/normativa; web proxy/public actions/data helpers/downloads/rendering; IA application/configuration; Supabase migrations; infra and scripts.

No target-controlled execution is approved yet. Trusted Cloudflare JSON validators run successfully in a cached Node Linux container without network, with read-only mounts, 128 MiB memory and 0.5 CPU. Full target sandbox, scratch disk/output bounds and race-safe evidence promotion are not yet demonstrated. Hunters perform source checks only (artifact:null); never run builds, tests, fixture code, live HTTP, Supabase, Redis, Ollama, cloud APIs or dependency installation. Existing fake-based Vitest, FastAPI MockTransport and rollback pgTAP tests are validation candidates, not observed results. Exact external or runtime blockers belong in needs_validation without severity.

Selected companion domains follow actual boundaries: HTTP/auth, browser rendering, tenant/data lifecycle, stored queue envelopes, resource parsing/quotas, IA context/output, cloud deployment and build inputs. Native-memory and desktop/mobile classes have no application implementation in scope. Parent alone owns shared ledger and reports. Agents return JSON and may write only within their assigned scratch, never artifacts or target source.
